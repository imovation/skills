# 排版踩坑清单（docx 附件册组装）

组装附件册（证据册）到中文法律文书 docx 时反复踩过的坑，先读这里再动手：

## 1. 附件册必须全由脚本控制分页，不要依赖 pandoc 生成的内容

- 坑：附件目录由 pandoc 从 md 的 `# 附件` 生成时，与正文不强制分页，清单可能被拆到两页（最后一页只剩孤行 1-3 行）。
- 法：正文 md 到落款即结束；附件册（标题 H1 + 目录清单 + 各附件）全部由 `build_attachments.py` 追加，脚本统一控制分页。

## 2. 图片段落必须是单倍行距

- 坑：format_docx.py 把全文统一为 1.5 倍行距——inline 图片的行高被行距因子放大（接近满页的图会整体下沉、被推到下一页，标题变成孤行）。
- 法：`build_attachments.py` 在 format 之后运行，把图片段落设为单倍行距＋零间距。

## 3. 长图限高必须预留标题占位

- 坑：A4 可用高度约 9.69in（边距上下 2.54cm），标题行约占 0.4in。限高设 9.5in 时"标题+图"总高超页，图片被挤到下一页，标题孤行——`keep_with_next` 拦不住超页图片。
- 法：图片限高 ≤ 9.2in（本脚本默认值），限宽 ≤ 5.7in（A4 可用宽 5.76in）。

## 4. pandoc 默认页面是 Letter，必须显式设 A4

- 坑：pandoc 参考文档默认 Letter（612×792pt），中文正式文书应为 A4（595×842pt）。
- 法：脚本对全部 section 设 21×29.7cm，边距上下 2.54 / 左右 3.18cm。

## 5. python-docx run 文本中的 `\n` 会自动转 `<w:br/>`

- 坑/法：目录清单可写在一个段落的多个 run 里，`\n` 自动换行；但注意这是段内软换行，不要与独立段落混淆。

## 6. 分页符并入标题段落，避免多余空行

- 坑：先加分页空段落、再写标题，每页顶部多一行空白。
- 法：标题段落第一个 run 加 PAGE break，标题文本在同一段落（本脚本做法）。

## 7. LibreOffice 锁文件勿提交

- 坑：LibreOffice/Word 打开 docx 时生成 `.~lock.<文件名>#` 锁文件，`git add -A` 会误提交。
- 法：`.gitignore` 加 `.~lock.*#`；误提交后 `git rm --cached`。

## 8. 落款对齐与页码

- 正式文书习惯：申请人签名与日期右对齐（`--align-signature`）；页脚居中页码「第 X 页」（宋体 10pt）。format_docx.py 不处理页脚，页码由 build_attachments.py 写入。

## 9. 渲染验证（不要只信 docx 结构）

- 结构正确 ≠ 布局正确（孤行/跨页/图片下沉只有渲染后可见）。每次组装后按 `reference/rendering-check.md` 转 PDF 逐页验证。

## 10. 正文首行缩进（中文文书规范）

- pandoc 输出的正文段落（Body Text / First Paragraph）默认顶格，中文正式文书应首行缩进 2 字符。
- 已并入 `format_docx.py`（`_set_first_line_indent`，24pt=2字符@12pt），自动排除：致送机关（"致："开头）、右对齐落款、列表项（Compact 样式）、图片段落、空段落。

## 11. 表格列宽（pandoc 等宽分配的挤压问题）

- 坑：pandoc 生成 100% 宽表格时各列等宽，"计算依据/说明"类长文本列被挤成多行，行高大。
- 法：按内容手动设置列宽（序号/短列收窄、长文本列放宽），A4 可用宽 14.64cm。python-docx 设 `column.width` 后需**同步 tblGrid 的 gridCol w 值**（1cm=567twips），否则 LibreOffice/Word 渲染可能不一致。本案示例：序号 1.0 / 项目 4.2 / 计算依据 6.8 / 金额 2.64 cm。
